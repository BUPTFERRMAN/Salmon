# BackTrace Demo 实现方案

## 1. 研究结论

### 1.1 从 MiroFish 当前仓库确认到的事实

- 当前后端是 `Flask`，前端是 `Vue + Vite`。
- 后端核心依赖包括：
  - `zep-cloud`
  - `camel-oasis`
  - `camel-ai`
- 代码结构说明它的主流程是：
  - 输入材料
  - 用 Zep 构图
  - 为 OASIS 生成 profile / simulation config
  - 运行仿真
  - 用报告代理总结仿真结果

### 1.2 结合网络信息后的判断

- `OASIS` 更适合“未来社会演化 / 多主体仿真”。
- `Zep` 更适合“长期记忆、图谱化关系、跨材料检索”。
- 对 BackTrace 这种 MVP 来说，真正必须先证明的不是大规模仿真，而是：
  - 能否把碎片材料结构化
  - 能否输出竞争解释
  - 能否把结论和证据绑定

因此第一阶段不直接复用 Zep/OASIS，而是保留它们作为第二阶段升级件。

## 2. 当前 Demo 架构

### 2.1 五层结构

1. 输入层
   接收聊天记录、案情时间线、事件片段和“要解释的结果”。

2. 结构化层
   先抽成消息、事件、角色、转折点、隐藏因素。

3. 推理层
   现在由轻量规则引擎实现，模拟以下几个代理：
   - 证据代理
   - 动机代理
   - 逆因果代理
   - 裁决代理

4. 结果层
   固定输出：
   - 主解释路径
   - 备选路径
   - 关键转折点
   - 缺证点

5. 展示层
   用单页静态界面渲染指标卡片、时间线、句级分析和解释路径。

### 2.2 当前已实现模式

- 对话回溯
  - 句级情绪
  - 句级候选意图
  - 关系温度
  - 冲突风险
  - 关键转折点

- 案情重演
  - 时间线重组
  - 高风险节点识别
  - 隐变量推断
  - 主 / 备选解释
  - 缺证点输出

## 3. 为什么这版先用规则引擎

### 优点

- 不依赖 API Key，拿到就能跑 demo。
- 输出稳定，适合先验证产品交互。
- 更容易把“证据约束”和“多路径解释”写死在结构里。

### 限制

- 标签粒度还比较粗。
- 对隐喻、反讽、复杂叙事理解有限。
- 案情重演还没有做到引用级证据绑定。

## 4. 第二阶段升级路线

### V0.2

- 加入可配置标签集
- 支持导入 `txt / md`
- 对聊天记录做更稳定的说话人切分

### V0.3

- 引入真实 LLM 做二次裁决
- 规则引擎只负责初判与保护栏
- 模型负责：
  - 排序解释路径
  - 补充缺失桥接
  - 生成更自然的报告文本

### V1.0

- 接入图谱层
- 给每条结论绑定 evidence span
- 支持“局面诊断”模式
- 支持材料补充后的二次回溯

4. 当两个标杆 demo 足够稳，再决定是否把 Zep / Graph 层接入。
