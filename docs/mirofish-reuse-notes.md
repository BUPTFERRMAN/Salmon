# MiroFish -> BackTrace 复用映射

## 已确认的可复用思想

1. 分层流水线
   MiroFish 的 `图谱构建 -> 仿真准备 -> 报告生成` 很清楚。BackTrace 保留这个分层意识，但把中间的“仿真”改成“逆因果推理”。

2. 中间层结构化
   MiroFish 在 `graph_builder.py` 里先把输入变成图谱。BackTrace 也采用同样思路，先构建事件、角色、转折点和假设，而不是直接输出长文。

3. 报告不是只有一个答案
   MiroFish 的报告层会组织多个观察结果。BackTrace 直接继承这个思路，主路径和备选路径一起输出，避免单路径幻觉。

## 当前不直接复用的部分

1. Zep 图谱服务
   适合后续做复杂证据网络，但不是 MVP 必需。现阶段先用本地事件结构跑通产品价值。

2. OASIS / CAMEL 大规模社交仿真
   这是 MiroFish 面向未来模拟的发动机。BackTrace 的关键不是“让角色自由演化”，而是“从已有痕迹回溯形成链”。

3. Report Agent 的超长推理工作流
   现在 demo 需要的是快速、稳定、可解释的结构化输出，所以先用规则引擎和固定 schema 兜底。

## 建议的第二阶段升级

1. 引入真实 LLM 做二次裁决
   规则引擎先给出候选路径，模型只负责重排、补证和语言润色。

2. 引入引用级证据绑定
   给每一条结论绑定原文 span，减少“像是真的”但找不到出处的问题。

3. 引入图谱层
   当材料从聊天记录扩展到文档包、新闻包、史料包后，再上图谱会更划算。
